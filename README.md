# Инструкции Моделкина

Редактор пошаговых инструкций и просмотр опубликованных версий по ссылкам. Сервер на Rust и Axum, PostgreSQL с миграциями SQLx, HTML-шаблон и статические CSS и JavaScript встроены в бинарник.

## Публикация

У каждой инструкции одна постоянная ссылка для каждого опубликованного уровня сложности. Новая публикация обновляет содержимое по существующим ссылкам. В админке предыдущие версии доступны в истории публикаций.

## Интерфейс из Figma

Редактор находится в `frontend/`. При push в `main` GitHub Actions собирает его из исходников. Docker встраивает полученные JavaScript и CSS в Rust-сервис. Для локального запуска через Cargo после редактирования интерфейса выполните `npm --prefix frontend ci` и `npm --prefix frontend run build`.

## Локальный запуск

Нужны Rust через rustup и PostgreSQL 17. Создайте локальную базу и пользователя, которому разрешено изменять её схему. В PowerShell, из папки проекта:

```powershell
$env:DATABASE_URL = 'postgresql://modelkin:LOCAL_PASSWORD@127.0.0.1:5432/modelkin'
cargo run --locked -- admin
cargo run --locked -- serve
```

Команда `admin` запрашивает логин и пароль от 12 символов и завершает предыдущие сессии при смене пароля. Почтовый сервис не требуется. По умолчанию приложение слушает [127.0.0.1:8000](http://127.0.0.1:8000). Адрес меняется через `MODELKIN_BIND`. Для HTTPS включите `MODELKIN_HTTPS=1`. Миграции проверяются при каждом запуске.

## Перенос существующих данных

В чистую базу PostgreSQL можно перенести данные из прежней SQLite. Для согласованной копии остановите старое приложение перед переносом:

```powershell
cargo run --locked -- import-sqlite data/instructions.sqlite3
```

Переносятся логин и пароль администратора, уровни, черновики, версии, изображения и токены ссылок. После переноса администратор входит заново. Пути `/read/…` сохраняются. Если меняется домен, старому адресу нужен HTTP-редирект с сохранением пути либо ссылку надо выдать на новом адресе. Импорт работает только с чистой целевой базой и оставляет исходный файл без изменений.

## Проверки и выкладка

`cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings` и `node --check static/admin.js` проверяют исходники. Для интеграционного теста задайте `TEST_DATABASE_URL` с адресом отдельной пустой базы и запустите `cargo test --locked -- --include-ignored`. Тест наполняет базу данными.
