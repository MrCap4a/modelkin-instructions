# Выкладка Моделкина

Домен сервиса — **моделкин.рф** (`xn--d1acjhedmc.xn--p1ai`). Изменения приложения отправляются в `MrCap4a/modelkin-instructions`, серверная конфигурация хранится в `lghdnov/infra`.

## Обновление

При push в `main` GitHub Actions проверяет код, собирает интерфейс и Linux-образ, поднимает его с отдельной PostgreSQL и проверяет `/healthz` и файлы редактора. Задание `publish` отправляет проверенный образ в GHCR с тегом SHA коммита. Тег `main` получает актуальная сборка. Для pull request выполняются проверки и сборка.

После первоначального подключения Doco-CD отслеживает `ghcr.io/mrcap4a/modelkin-instructions:main` для отдельного проекта `modelkin-instruction`. Сверьте ответ `curl -fsS https://xn--d1acjhedmc.xn--p1ai/healthz` с `git rev-parse HEAD`: это хеш версии, которая действительно отвечает через HTTPS.

## Первое подключение

1. В DNS-зоне моделкин.рф добавьте A-запись `@` со значением `82.114.228.159`.
2. Первый push приложения создаёт пакет в GHCR. Подтвердите, что Doco-CD может его скачать. Для закрытого пакета используйте настроенный доступ на чтение. Для публичного пакета проверьте анонимное скачивание.
3. В инфраструктурном репозитории примените ветку с каталогом `modelkin/`, записью в `.doco-cd.yml`, зашифрованными SOPS-файлами и маршрутом в Caddyfile. Контейнер приложения подключается к `compose_caddy`, PostgreSQL использует отдельную сеть и постоянный том. Сервис получает роль своей БД, пароль суперпользователя доступен только контейнеру PostgreSQL.
4. Перед созданием единственного аккаунта решите, нужно ли переносить накопленные инструкции. Для переноса существующей базы используйте согласованную резервную копию. Импорт старой SQLite выполняется командой `import-sqlite` в чистую базу, как описано в основном README. Без переноса выполните команду ниже через SSH, чтобы задать новый логин и пароль.

```sh
app=$(docker ps -q --filter label=com.docker.compose.project=modelkin-instruction --filter label=com.docker.compose.service=app)
docker exec -it "$app" modelkin-instruction admin
```

## Резервная копия и откат

```sh
umask 077
db=$(docker ps -q --filter label=com.docker.compose.project=modelkin-instruction --filter label=com.docker.compose.service=db)
docker exec "$db" pg_dump -U modelkin -Fc modelkin > "modelkin-$(date +%Y%m%d-%H%M%S).dump"
```

Для отката укажите в `modelkin/docker-compose.yml` инфраструктурного репозитория тег последнего исправного SHA вместо `main`, примените изменение и проверьте `/healthz`. Том БД сохраняется. Возврат образа не отменяет миграции, поэтому при несовместимых изменениях схемы потребуется согласованное восстановление БД. После исправления верните тег `main`.
